# 无短码交互与提醒消息到点自动发送

日期：2026-10-06。状态：推荐方案已整理，等待用户复核；尚未修改代码或线上发送规则。

## 需求与方案

用户要求去掉截图中的四位任务短码，并让到点的提醒直接发送、不再临时请求批复。截图走的是旧委派入口，而非已上线的私人留言入口。

两个范围方案：
- 推荐：提醒、留言、通知进入独立消息流程；创建时核对并确认一次，到点自动发送。正式工作任务继续保留到点审批，但所有用户交互取消短码。
- 另一方案：正式工作任务也到点自动下达。改变任务授权规则，范围更大；本规格不采用，除非用户明确另行选择。

## 发送规则

- “给某同事发消息/发送一条消息/发提醒/发通知”等明确消息请求，不再创建 delegated_tasks；支持截图中的“1分钟后给谭筱莹发消息提醒他4点下班”。
- 显式“下达任务/委派任务/安排任务”仍进入工作任务流程；仅有“提醒我”属于个人提醒，不能拦截成给同事发消息。
- 消息接收人只能从已启用私人留言名单精确匹配姓名、已登记别名或明确UserID。未知、同名或停用账号要求澄清，不能把谭颖、刘颖、谭筱莹互相猜成同一个人。
- 首版名单不扩大：负责人、刘颖、蛋挞、谭筱莹；舍得仍不加入。新同事需要另行登记及明确开通权限。
- 新消息先给发件人预览收件人、正文、北京时间；本人“确认发送”授权一次。到点不再出现“待批准下达”或请求二次批复。
- 发送时间用本地有限语法解析；正文不发送给AI，也不改写。无冒号时只拆分明确的收件人/消息意图/正文边界，不猜测模糊输入。
- 留言/通知不创建待办、不触发任务催办；任务原有跟踪规则不变。

## 无短码交互

- 企业微信所有委派、审批、下达、跟进、进展和异常提示，以及网页委派列表，均不显示四位短码、不要求输入短码。
- 新任务不再生成短码；历史 approval_code 等字段可留作数据兼容，但不能成为新交互或身份凭证。内部用UUID、状态和版本关联。
- 单一可操作记录直接按明确命令处理；多条时显示姓名、摘要、时间，以当前菜单临时序号选择。菜单按真实发送人和空间隔离，10分钟到期。
- 改动后旧菜单版本不能授权新正文；选择前重新核对身份、目标、状态和版本，条件更新防止重复处理。
- 任务和留言菜单不能抢占彼此的数字回复。统一当前菜单归属或等价协调机制；“任务收到”和“留言收到”明确区分。
- 普通“收到/取消/修改”等有歧义时先选择，不凭AI或最近一条消息猜目标。
- 正式任务的批准仅限负责人；同事只处理发给自己的任务。负责人不是私人会话一方时没有正文查看权限。

## 兼容与异常

- 旧委派记录继续原有审批规则，不批量改成自动发送；不补发历史过期、失败或不确定记录。
- 已发送的消息不能撤回或重发来“去掉短码”；新发送边界采用无短码模板，保留正文数字，并核对原确认版本。
- 消息继续复用持久化队列与唯一操作键；明确失败最多两次尝试，结果不确定立即暂停。超计划时间15分钟的消息暂停，不能重启后突然补发。
- 发送前再次检查双方权限和目标身份；停用、跨空间或第三人操作拒绝。不扩大应用可见范围，不发送真实测试消息。
- 选择上下文和历史字段变更使用独立迁移；所有服务角色查询显式限制空间/负责人，并校验当前操作人。不向客户端授予额外正文权限。

## 实施与验收

- 复用私人消息的解析、授权和出站服务，扩展确定性消息意图入口；委派只处理正式任务。
- 调整委派文案、命令解析与选择上下文；修改网页短码显示，必要迁移只新增控制数据并放宽历史短码字段的非空要求，不删除历史任务。
- 先写失败测试，再实现：自然消息请求走私人流程、正式任务保留审批、所有模板/网页无短码、无短码多记录选择、身份隔离、旧菜单失效、数字回复跨业务、旧任务不自动补发、否定/个人提醒不误匹配。
- 完整后端回归、前端构建及桌面/手机现有委派流程验证；自动测试全用替身发送，不给真实同事发消息。
- 用户批准规格后才制定实施计划；测试通过后分步骤迁移、部署、开启，并由知情双方实测。

## 自审

范围按推荐方案明确限定；无占位项。到点免批仅针对一次确认后的消息，不包含正式任务。保留历史数据不等于继续显示或要求输入短码。当前未实施，不宣称线上行为已变化。
