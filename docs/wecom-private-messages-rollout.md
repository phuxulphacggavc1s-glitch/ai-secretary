# 企业微信私人定时留言上线说明

核实日期：2026-10-06。当前代码已在本地实现，尚未执行生产迁移、成员登记、部署和真实消息联调。用户批准设计不代表授权向真实同事发送测试正文。

## 范围与注意事项

首版只有企业微信文字入口。参与人限定为负责人本人、刘颖、蛋挞、谭筱莹；舍得不参与。普通应用使用权限只允许留言双方查看正文，服务器和数据库运维权限不是端到端加密。

留言没有可见短码。多条需要区分时显示姓名、摘要、时间和当前菜单的临时序号。正文不发给AI，也不写入个人任务、委派、秘书记忆或旧回调正文表。

## 上线顺序

1. 保存服务器当前版本和配置的受限访问备份。留言独立开关保持 WECOM_PRIVATE_MESSAGES_ENABLED=false；不修改原有委派开关。
2. 在正确的 Supabase 项目执行 supabase/upgrade_v8_private_messages.sql 全文。迁移通过事务新增六张表、约束、索引及服务端权限，不修改现有任务。SQL Editor 和迁移执行方式、RLS与权限要求已核对 [Supabase RLS官方文档](https://supabase.com/docs/guides/database/postgres/row-level-security)。
3. 确认六张表开启RLS，anon/authenticated没有读写权限，也没有允许客户端读全部正文的策略。服务端使用service-role，仍需应用层空间与参与人校验。
4. 私下登记四人的准确企业微信UserID、姓名及必要别名；空间ID使用现有负责人Supabase身份。不要公开提交个人映射，也不要把同事加入负责人 WECOM_APP_USER_MAP。private_message_participants 默认不启用；确认每个人身份后再启用其 active。成员id、空间、UserID不可修改重绑定；若登记错误，停用原记录后以新身份登记。
5. 核验参与人在应用可见范围和基础接口许可范围内。企业微信官方说明，超范围/未获许可成员可能通过 invaliduser/unlicenseduser 返回拒收，不能只看 errcode=0：[发送应用消息](https://developer.work.weixin.qq.com/document/path/90236)。此处不猜测后台菜单位置；如界面不同，先根据当前官方后台核验。
6. 在独立开关关闭时部署后台代码，重启现有单实例服务并检查健康状态及原有委派。不要另启第二个带调度器的进程。无需新增前端页面或给同事创建网站登录账号。
7. 数据库、登记、回调和权限通过后，获得用户明确开启授权，再设置 WECOM_PRIVATE_MESSAGES_ENABLED=true 并重启。
8. 两名知情参与人按下列流程实测。真实发送须单独确认具体收件人、正文和时间。通过后再允许四人正常使用。

## 验收用法

- 给乙留言，立即发送：交接测试。先收到自己的预览，确认发送前乙不应收到。
- 明天9点给乙留言：交接内容。核对北京时间后回复“确认发送”，到点自动发送，不经过负责人审批。
- 修改留言：更新内容。旧确认撤销，须再次确认。改时留言：明天10点；取消留言仅对未发送留言生效。
- 乙收到后回复“留言收到”，只有原发件人收到回执。回执是主动确认，不代表平台已读。
- 回复留言：补充内容。只能回到同一会话另一人；默认确认后立即发，也可使用“回复留言，明天9点发送：内容”。
- 多条时按当前菜单临时序号选择；10分钟过期或记录状态变化后需重新选择。
- 第三人、舍得、停用账号不能访问；负责人不是会话方也不能从应用读取正文。收件人不能提前查看未发送内容。
- 检查不产生个人任务、不触发催办、不进入AI请求或旧正文记录。重复回调和扫描不能重复发送。
- 模糊时间不猜测。“下周”“月底”等首版需改成明确日期时刻；已过去的时间须重填。正常每分钟扫描，以两分钟内开始发送为目标，不承诺秒级到达。

## 故障与停用

明确失败最多两次发送尝试，然后保留记录并暂停；无需再取消。无法确定平台是否接收时立即暂停，先向收件人核实，不能直接重发。发送成功但发件人通知失败不会重发正文。

超过计划时间15分钟的未发送记录暂停，避免重启后突然补发过期交接。关闭独立开关暂停调度并拦截留言命令，不回退到普通秘书正文存储。恢复开关前先核对记录；超时记录不自动补发。

持久化出站操作键和条件更新防止同一次授权重复投递。平台的按内容去重关闭：没有可见短码时，用户两次独立确认的相同文字也可能完全相同，不应被平台误吞。官方定义此开关为相同请求JSON去重，0为关闭：[企业微信发送应用消息](https://developer.work.weixin.qq.com/document/path/90236)。网络结果不确定时不自动再次请求。

回退时关闭留言开关并恢复已备份代码；保留新增表和记录，不删私密数据。日志只留安全错误分类，不输出正文、密钥、凭证或完整平台响应。
