# 无短码交互与到点自动消息上线说明

日期：2026-10-06。用户已确认设计。本文对应本地实现；生产 v9 迁移、代码部署及真实双方联调尚未完成。不要把本地模拟发送通过当成真实送达。

## 变更范围

- 定时发消息、留言、通知、提醒进入私人消息流程：创建时核对一次预览并回复“确认发送”，到点直接发送，不进入任务审批或催办。
- 明确的正式任务委派仍由负责人到点批准。新任务不生成短码；所有新控制文案和网页列表不显示短码。
- 多条记录使用当前菜单临时序号，按操作人和空间隔离，10分钟过期。新菜单使另一业务的旧菜单失效。
- 历史任务不转成自动消息，不批量重发。正文中的订单号、时间和其他数字原样保留。
- 私人名单不扩大：负责人、刘颖、蛋挞、谭筱莹；舍得仍不参加。谭颖不是这三位同事的别名，未登记时明确拒绝而不猜人。

## 验收

- “1分钟后给已登记同事发消息提醒他4点下班”：只出现收件人、正文和发送时间预览，不出现四位短码或任务审批。确认前收件人不应收到。
- 回复“确认发送”：确认一次；到点发送一次，不再请求批复，不生成待办或任务催办。
- 发送时间与正文中的“4点下班”分开，订单数字不变；时间不明确要求补充，不调用AI猜测。
- “明天9点给同事下达任务：工作内容”：仍需负责人到点批准，但用“批准任务/取消任务/修改任务：内容”，无短码。
- 同事任务回复使用“任务收到/任务完成/任务进展：内容”；私人回执使用“留言收到”。有多条时先选当前菜单，不能根据最近一条猜对象。
- 两种业务交替打开菜单，旧数字选择不能执行旧业务。不同人的菜单互不影响，修改内容后旧选择不能批准新正文。
- 未登记、停用、第三方或舍得账号不能操作私人消息；谭颖不自动映射到刘颖或谭筱莹。
- 重复回调及重复扫描不重复发送。两次独立确认的相同内容不能被错误合并。
- 历史成功出站记录不重发，未批准任务不自动下达，失败/不确定消息暂停处理。

## 故障与回退

先停止后台处理并记录安全错误分类，核对发送是否已被平台接收；结果不确定时不得直接重发。保留所有任务、消息及队列，不删除数据或回填虚构短码。

v9迁移向前兼容，不需要删表回退。若已产生无短码新任务，不应直接恢复依赖旧短码交互的代码；保持发送暂停，优先修复当前版本。仅在核查没有新版本业务记录及出站状态后，才可按备份恢复旧代码/前端。原有业务开关的改变需明确告知用户。
